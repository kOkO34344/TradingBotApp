# FTMO execution venue, via cTrader Open API.
#
# This package hard-pins protobuf==3.20.1, Twisted==24.3.0, pyOpenSSL==24.1.0,
# requests==2.32.3 and cryptography<43. Installing it DOWNGRADES protobuf from
# 7.x — verified safe on 2026-08-02 and worth re-checking if either package
# moves: yfinance is the only other protobuf dependent in this project and its
# own floor is protobuf>=3.19.0, so 3.20.1 satisfies it. Confirmed functionally,
# not just by resolver: daily bars, hourly bars, FX crosses and Ticker.history
# all return real data on 3.20.1, and torch/huggingface_hub/safetensors do not
# depend on protobuf at all.
#
# Do NOT "fix" the downgrade by dropping yfinance. It is the data source behind
# grade_calls.py (the only route to graded evidence, rule 5), every backtest,
# and every IC screen this project has run.
ctrader-open-api

# Twisted needs service_identity for proper TLS hostname verification — without
# it you get "rudimentary" verification on the socket that carries your broker
# credentials. The two constraints below are NOT cosmetic and were both learned
# by breaking the venv on 2026-08-02:
#   - pyOpenSSL 24.1.0 (pinned by ctrader-open-api) requires cryptography<43.
#     A bare `pip install service_identity` pulls cryptography 50.x, which
#     breaks pyOpenSSL at import with "module 'lib' has no attribute
#     GEN_EMAIL" and takes the whole cTrader client down with it.
#   - service_identity >= 25 requires cryptography>=47, so it cannot coexist
#     with that ceiling. 24.2.0 is the newest that works.
cryptography>=41.0.5,<43
service_identity<25
